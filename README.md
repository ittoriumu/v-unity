# Jewels×Duel

2人用対戦カードゲーム「Jewels×Duel」の Web 版です。ビルド不要の静的ファイルだけで動きます。

## 遊び方

- **オンラインで遊ぶ**：上のボタン（<https://ittoriumu.github.io/v-unity/>）を開くだけです。
  ※ GitHub Pages を有効にした後に表示されます（有効化は下記）。
- **手元で遊ぶ**：リポジトリを「Code → Download ZIP」でダウンロードして解凍し、`index.html` をダブルクリックしてブラウザで開きます。

<details>
<summary>GitHub Pages の有効化手順（リポジトリ管理者向け）</summary>

1. ゲーム一式を `main` ブランチに反映する（プルリクエストをマージ）
2. リポジトリの **Settings → Pages**
3. **Build and deployment → Source** を「Deploy from a branch」にし、Branch を `main` / `/ (root)` にして **Save**
4. 1〜2 分後に <https://ittoriumu.github.io/v-unity/> で公開されます

</details>

## できること

| 機能 | 内容 |
|---|---|
| **CPU 対戦** | 先攻・後攻／CPU の強さ（かんたん・ふつう・つよい）／動作速度を選べます |
| **デフォルトカード** | 6 色 × 12 枚 + 混色 6 枚 + 追加 2 枚 = **80 枚**（ルミナ 46・スペル 28・ステージ 6）と、6 種のプリセットデッキ（各30枚） |
| **デッキ構築・カード図鑑** | 色・種類・テキストで絞り込み。30 枚・同名 3 枚まで。LV 分布グラフ。保存可能 |
| **オリジナルカードエディタ** | ブロックを組み合わせて効果を作る **ビジュアルプログラミング** |
| **コスト自動設定モード** | ステータスと効果の価値から LV／カラーコストを自動決定。強すぎるカードは作れません |
| **コスト自由設定モード** | LV とカラーコストを自由に指定。バランス評価（割高〜強すぎ）は参考表示 |
| **イラスト取り込み** | ファイル選択／ドラッグ＆ドロップ／クリップボード貼り付け → 位置・ズームを調整して保存 |
| **カードの書き出し・読み込み** | JSON（イラスト込み）。読み込み時は内容を検証・無害化します |

オリジナルカードやデッキはブラウザの `localStorage` に保存され、そのままデッキ構築・CPU 対戦で使えます。

## ブロックプログラミング

カードは「トリガー」の中に「ブロック」を積んで作ります（パレットからドラッグ、またはクリックで追加。外へドラッグまたは × で削除。`もし〜なら` `くり返す` は入れ子にできます）。

- **トリガー**（ルミナ）：登場時／アタック時／ダイレクトアタックした時／ルミナにダメージを与えた時／破壊された時／自分のターン開始時／常時
- **トリガー**（ステージ）：登場時／上にルミナが出た時／上のルミナがアタックした時／上のルミナが破壊された時／自分のターン開始時／常時
- **色ごとのブロック**（原文の得意分野に対応）
  - シアン（山札・手札）：ドロー／ルーター／サーチ／山札破壊／手札破壊／バウンス
  - マゼンタ（場・アタック・ダメージ）：プレイヤーダメージ／ルミナダメージ／ダウンさせる／アップ／ステージフリーズ解除／ショーケース増加
  - イエロー（パワー・タフネス・バフ）：バフ／デバフ／ダメージ回復／常時：条件付きバフ・種族ロード・ステージバフ
  - グリーン（ジュエルゾーン）：ジュエルフロー追加／山札からジュエル／ジュエル破壊／ジュエル回収
  - ブラック（トラッシュ・ライフ）：トラッシュ回収／ルミナ蘇生／ライフ回復／自傷／生贄／破壊
  - ホワイト（染色・移動）：染色／ルミナ移動／相手ルミナ移動／ショーケース移動／常時：染色
  - 制御：`もし〈条件〉なら`／`N回くり返す`

他色の得意ブロックを使うと、**その色のカラーコストも要求されます**（例：シアンのカードにマゼンタのダメージを載せると M が必要）。

## コストとバランスの仕組み

1. すべてのカードに「価値（pt）」を付けます（パワー・タフネス＋各ブロックの価値 × トリガー倍率）。
2. LV ごとに許容できる価値の上限があり（ルミナ・スペル・ステージで別カーブ）、上限を満たす最小の LV が自動コストになります。
3. カラーコスト合計は `ceil(LV/3)`、他色ブロックがあればその色を各 1 追加。
4. **デフォルトカードもエディタと同じ計算式でコストを決めています**（原文の例 `シアン/LV6/C2/メモリア・クリスタ・クォーツ/1/2` だけは指定どおり固定）。

### 自己対戦によるキャリブレーション

係数（色ごとの効果係数・パワー/タフネス係数など）は、CPU 同士の自己対戦の勝率が揃うよう山登り法で調整しました（`tools/calibrate.js`）。

プリセット 6 デッキの総当たり（各対戦 150 戦、先後交互、CPU＝ふつう、計 2,250 戦）：

| デッキ | 勝率 |
|---|---|
| シアン：記憶の図書館 | 57.6% |
| マゼンタ：栄光の騎士団 | 50.7% |
| イエロー：宝石の巨人 | 52.1% |
| グリーン：森の恵み | 44.0% |
| ブラック：黄昏の墓所 | 48.1% |
| ホワイト：伝説の証 | 46.5% |

全デッキが 44〜58% に収まり、先攻勝率は約 55% です。平均ゲーム長は全体で約 12 ターン（片側 6 ターン程度）です。
原文の設計思想に合わせ、パワーは 0〜1 が標準、2 は LV4〜6、3 は LV8 相当の「ごく稀」な水準です。

> この数値は CPU の打ち方に対するものです。人間同士では傾向が変わり得ます。カードや係数を変更したら下のツールで再検証してください。

## 開発用ツール（Node.js のみで動作、`tools/`）

エンジン・ブロック・コスト算出・AI は DOM に依存しないので、Node で単体実行できます。

```sh
node tools/sim.js 100 normal      # プリセット総当たりの勝率表（引数：1組あたりの対戦数, easy|normal|hard）
node tools/diag.js 30             # カード別の「使われた試合の勝率」
node tools/calibrate.js 30 24     # 係数のキャリブレーション（山登り法）
node tools/rules-test.js          # ルール適合テスト（37項目）
node tools/fuzz.js 300            # ランダム生成オリカ×AI 対戦のクラッシュ／ハング検査
```

ブラウザ操作の自動テスト（Playwright + Chromium が必要）：

```sh
NODE_PATH=$(npm root -g) node tools/smoke.js /tmp/shots        # 起動〜対戦開始
NODE_PATH=$(npm root -g) node tools/ui-flow.js /tmp/shots      # 対象選択・アタック・ジュエルプレイ・終了時セットアップ
NODE_PATH=$(npm root -g) node tools/editor-test.js /tmp/shots  # エディタのドラッグ＆ドロップ／デッキ構築
NODE_PATH=$(npm root -g) node tools/art-test.js /tmp/shots     # イラスト取り込み／JSON 入出力
```

## 原文が明記していない部分の解釈

ゲーム内の「ルール」ページにも記載しています。

- 山札切れ：山札から引く／トラッシュする必要があるのに 1 枚も無い時に敗北。両者が同時に 10 枚に達した場合はターンプレイヤーの勝ち。
- 1 レーンにルミナは 1 体まで。ステージは置き換え可能（古いステージは破壊）。ショーケースは最大 3 レーン。
- ジュエルのコストは消費せず「必要条件」として判定。ルミナは出すレーンのジュエルエリア、スペル・ステージは全ジュエルエリアの合計で判定。
- セットアップは 1 ターン 1 回・好きな数を選択。ターンの開始時（他の行動の前）か終了時。ドローは行動に数えません。
- 染色ブロックは「置き換え」、常時効果の染色は「元の色に加えて指定色としても扱う」。
